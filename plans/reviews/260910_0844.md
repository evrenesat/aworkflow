1. **P2 — Preserve lifecycle bootstrap admission for a new directory.** High confidence. `aflow/api/startup.py:396–401`.
   - Scenario: start a lifecycle workflow with a valid new plan in an existing directory that has not yet been initialized as a Git repository.
   - Evidence: `prepare_startup` now calls strict `preflight_worktree`, but its non-repository exception path only allows workflows without setup. A temporary fixture using the existing lifecycle test configuration raises `StartupError: worktree preflight inspection failed` before a prepared run can reach bootstrap. At the CP6 base, `_check_worktree_dirtiness` returns normally when `probe_worktree` returns None. `_lifecycle_is_bootstrap_eligible` still explicitly supports NOT_A_REPO and UNBORN; ARCHITECTURE documents this bootstrap path.
   - Impact: the documented automatic initialization path is unreachable through normal startup for new non-Git projects.
   - Smallest fix: distinguish the existing bootstrap-eligible non-repository state at startup and defer Git-dependent inspection until bootstrap creates the repository. Keep strict inspection errors for real checkouts and retain post-bootstrap validation. Add a temporary-directory startup regression and a real-checkout inspection-failure regression; do not broadly swallow Git errors or represent arbitrary failures as clean.

2. **P2 — Inspect operation markers only for the selected worktree.** High confidence. `aflow/git_status.py:434–436`.
   - Scenario: the primary checkout has an in-progress merge, while a separate linked worktree is clean and is selected for a same-checkout workflow.
   - Evidence: `_in_progress_git_operation_markers` checks both the selected worktree Git directory and the common Git directory. These operation markers belong to individual worktrees. A disposable repository with a real conflicting merge in the primary checkout yields `dirty=False` for the linked checkout but returns `in-progress Git operation (MERGE_HEAD exists)`. Startup rejects that unrelated blocker. The CP6 dirty probe admitted the clean linked checkout.
   - Impact: an operation in a separate checkout unnecessarily blocks launching against a healthy selected worktree.
   - Smallest fix: resolve and inspect operation markers in the selected worktree's Git directory only; remove the redundant common-directory scan. Add a linked-worktree regression with an actual merge conflict in the primary checkout, and retain refusal when the selected worktree itself has an operation/conflict.
