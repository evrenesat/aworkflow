## Finding

P2 — High confidence — `aflow/status.py:1312–1319`: Emit changed plan paths at finalization before recording them as emitted.

When a review finishes and the workflow switches the active plan to a repair overlay, `_emit_update` chooses only the finalized-turn formatter. That formatter sees the completed record's old active plan, not the new projection's active plan. The new projection is then saved as the last emitted state, so the following worker's formatter treats the repair path as unchanged and omits it too. The CLI can therefore run the repair worker without ever showing its active plan until the final run summary. This violates original layout rule 9 and hides the file the next worker is acting on.

Evidence: `aflow/workflow.py:10995` sets the newly selected active plan before `banner.update(state)`. A synthetic review-finalization → repair-worker transition reported `repair_path_visible_before_stop: False` while `new_worker_visible: True`. The same emission gap affects generated-plan changes in turn blocks and preparation updates, which do not append that field even though it participates in projection comparison.

Smallest coherent fix: emit newly changed active/generated plan paths consistently in preparation, turn-finalization and running-turn paths before advancing the last-emitted projection. Reuse the existing path formatting and avoid repeating unchanged paths or complete turn blocks. Add focused synthetic regression coverage; retain checkpoint attribution and all existing behavior.
