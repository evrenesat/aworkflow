## Findings

1. **P2 — High confidence: dark screenshots are captured in light mode.**
   `apps/aflow_app/server/tests/test_responsive_browser.py:448–451`.
   The loop sets only the current document's theme, then immediately navigates
   to a new document. App initialization restores the saved/system appearance,
   which is light in this browser context. Every dark-labelled route capture
   therefore misses the required dark-mode acceptance. A disposable Chromium
   probe returned `THEME_AFTER_GOTO light`; the fresh WebKit
   `responsive-dark-skills-detail.png` was visually inspected and is light.
   Smallest fix: persist the intended appearance through the existing preference
   mechanism before navigation and assert the resolved theme before every capture,
   including landscape routes. Regenerate and inspect both themes.

2. **P2 — High confidence: the 200% check does not enlarge editor text.**
   `apps/aflow_app/server/tests/test_responsive_browser.py:392–400`.
   Changing only html font size scales rem-based elements but leaves the body
   and text editors' explicit 16px rules in place. The probe measured the Skills
   editor at 16px before and after this exact injection. The test can pass while
   clipping or obscuring genuinely enlarged editing controls, so it does not
   establish CP6's required text-enlargement acceptance. Smallest fix: use a
   test-only enlargement method that doubles actual rendered text, verify computed
   font sizes for representative prose and editing controls, and then check
   reflow and final-action/focused-control reachability at the required widths.
   Preserve production typography unless the corrected check exposes a defect.
